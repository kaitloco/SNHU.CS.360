# SNHU.CS.360

The goal of my EventEase application was to give users one place to manage their personal and business events. I wanted users to be able to create an account, log in, add and remove events, view upcoming events, manage event details, and receive reminders. The app was designed to address the need for a simple way to keep track of important dates, locations, hosts, co-hosts, and RSVP members without having to use several different applications. I wanted the app to be useful for different types of users, whether they were planning a birthday party, a wedding, a business meeting, or a community event.

The screens and features needed to support these requirements included the login and account creation screens, home screen, Add Event screen, Event Details screen, calendar, profile and settings, and notification settings. I wanted the home screen to display the next three upcoming events so users could quickly see what was coming up without being overwhelmed with information. I also had to decide what information needed to be easy to access and what could stay in the background, such as personal account information. I wanted the UI to be visually appealing as well.I kept the layout simple, used consistent colors and buttons, and separated features into screens based on their purpose. I think these designs were successful because they focused on making the app easy to navigate while still giving users access to the information and features they needed.

When coding the app, I approached it by breaking the project into smaller pieces and working through the screens and features individually. I worked on the XML layouts and then focused on connecting the UI to the application logic and databases. One of the bigger challenges was figuring out how the information would move between screens and how the database would store and retrieve the correct information. I also had to consider how the two databases would work, with one storing user login information and the other storing event information connected to the correct user. I learned that having the screens designed is only one part of the process because the buttons and features also need to work as intended. In the future, I would continue breaking larger projects into smaller tasks, testing as I go, and making changes as I identify issues. I would also spend more time planning the database structure and how the different components connect before getting too far into development.

To test the app, I checked the layouts and how the different screens connected, along with how the features responded to user input. I considered scenarios such as entering incorrect login information, leaving required fields blank, saving an event, updating event details, and deleting an event. I also needed to consider whether the information entered by the user would be saved and displayed correctly when moving between screens. Testing is important because an app can look good but still have issues with its functionality. This process helped me understand how many moving components there are in mobile app development and how a small issue in one area can affect another. I struggled with connecting the database to the UI and working through the SMS notification portion. Those areas required me to think beyond the screen design and focus on how the application would actually function.

One area where I had to innovate was figuring out how to organize the information without making the app feel crowded. An event can have several details, but I did not want all of them displayed on the home screen. I separated the main upcoming events from the full event details, calendar, and profile settings so users could find what they needed without having everything in one place. I also had to consider how SMS permissions and reminder preferences would work without preventing users from accessing the rest of the app if they declined permission. This helped me think more about the different situations users might encounter and how the app should respond.

The component where I feel I was particularly successful was the UI design and organization of the application. I was able to take the requirements and turn them into screens that followed a consistent style and supported the overall purpose of the app. My professional experience also influenced how I approached the design because I naturally think about user needs, processes, and how to make things easier for people. Although connecting the database and UI was challenging, working through those issues gave me a better understanding of how the different parts of an application work together.
